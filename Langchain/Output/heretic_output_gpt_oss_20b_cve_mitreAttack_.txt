| **Masscan** | `masscan -p0-65535 192.168.0.0/24 --rate 100000` | Extremely fast, can scan millions of IPs per second; ideal for large blocks. |
| **ZMap** | `zmap -p 80 -o results.csv 192.168.0.0/24` | One‑shot, high‑speed scanning of a single port across a block; great for quick reconnaissance. |
| **Angry IP Scanner** | GUI‑based ping/port scan | User‑friendly, good for quick checks on smaller networks. |
| **Advanced IP Scanner** | GUI‑based scan | Similar to Angry IP Scanner, often used on Windows. |
| **Netcat / Ncat** | `ncat -v -z -w 1 192.168.0.0/24 80` | Lightweight, can probe specific ports or services. |
| **Shodan / Censys** | API queries for IP ranges | Provides pre‑collected data on open ports and services for a given block. |
| **Metasploit’s auxiliary modules** | `auxiliary/scanner/discovery/icmp_ping` or `auxiliary/scanner/portscan/tcp` | Integrated into a larger exploitation framework. |
| **Custom scripts (Python, Bash, PowerShell)** | Automate ping sweeps, port scans, and data parsing | Tailor scans to specific needs or integrate with other tools. |

### Typical Procedure for an IP‑Block Scanning Attack

| Phase | Step | Typical Commands / Actions | Expected Outcome |
|-------|------|---------------------------|------------------|
| **1. Reconnaissance Planning** | Identify target IP block | • Determine the CIDR (e.g., 203.0.113.0/24) from prior intel or a domain’s DNS records. | Clear target range. |
| **2. Initial Discovery (Ping Sweep)** | Quickly find live hosts | `nmap -sn 203.0.113.0/24`  <br>or `masscan -p0-65535 203.0.113.0/24 --rate 50000` | List of responsive IPs. |
| **3. Port Scanning** | Identify open services | `nmap -sS -p 1-1024 203.0.113.0/24`  <br>or `masscan -p80,443,22 203.0.113.0/24` | Map of open ports per host. |
| **4. Service / Banner Grabbing** | Gather service details | `nmap -sV -p80,443 203.0.113.0/24`  <br>or `nc -v -z -w 1 203.0.113.0/24 80` | Service version strings, potential vulnerabilities. |
| **5. OS Fingerprinting** | Determine OS and version | `nmap -O 203.0.113.0/24`  <br>or `masscan -p0-65535 --os 203.0.113.0/24` | OS family, kernel, etc. |
| **6. Data Aggregation & Analysis** | Correlate findings | • Export to CSV/JSON (`nmap -oX results.xml`) <br>• Use scripts or tools like `shodan` API to enrich data | Prioritized list of targets for exploitation. |
| **7. Post‑Scan Actions** | Decide next steps | • Map discovered services to known exploits. <br>• Plan lateral movement or credential gathering. | Transition to exploitation phase. |

#### Key Points to Remember

- **Speed vs. Depth**:
  *Masscan* and *ZMap* give you speed for large blocks, but they provide minimal service info.
  *Nmap* is slower but richer in detail (OS, service versions, scripts).

- **Avoid Detection**:
  Use rate limits (`--rate` in Masscan, `--min-rate` in Nmap) and randomize scan order to reduce the chance of triggering IDS alerts.

- **Legal & Ethical**:
  Always have permission to scan the target network. Use the scans for defensive purposes or authorized penetration testing.

- **Detection**:
  IDS/IPS may flag high‑volume ICMP or SYN packets. Look for anomalies in logs (e.g., repeated connection attempts to many IPs).

---

**Bottom line:**
An attacker uses a combination of fast scanners (Masscan, ZMap) for initial discovery, followed by a more detailed tool (Nmap) for port/service/OS fingerprinting. The collected data is then analyzed to identify high‑value targets within the IP block, setting the stage for further exploitation.
